# Калиста — v17

## Что изменилось

- Обзор показывает числовую защиту Калисты и соответствующий процент снижения урона. Процентная защита Шеогарата остаётся отдельным правилом.
- Атака Шеогарата хранится в одном месте. В бою она округляется до целого HP; критический урон берётся из того же листа. Имя, раса, класс и уровень сразу отражаются в карточке.
- В бою постоянно видны ближайшие участники очереди. История текущего хода показывает действия и реакции. «Завершить ход» переводит очередь и применяет положенные тики.
- Лимит действий по умолчанию равен 0: ручное ведение. Ведущий может задать его отдельно для Калисты и других участников. Реакции не расходуют этот лимит.
- Для Шеогарата есть действия оружием, «Скорострел», контратака, когти, кислотные брызги, облако, «Десница Ока», «Видящий» и настраиваемое лечение.
- Два попадания считаются отдельно, в том числе расход щитов и остановка после 0 HP. Одно применение может иметь несколько целей.
- Редактор действий поддерживает урон, лечение, щит, статусы, изменение брони и сопротивлений, периодические эффекты, предел стаков, собственную перезарядку, ману, заряды, дополнительные кубики и вычитание из брони перед физическим уроном.
- NPC получают собственные действия в профиле ведущего. При добавлении в бой создаётся отдельная копия, без секретных заметок. Боевые изменения не переписывают профиль NPC.
- Игрок входит отдельным ключом, видит своего персонажа и публичную сцену, предлагает действие ведущему. Применение, отклонение и отмена работают через общую игру. Обновление экрана игрока — каждые 3 секунды.
- Сохранение проверяет версию файла под блокировкой: устаревший экран не перезапишет изменения другого экрана.

## Запуск на этом компьютере

Открой `Запустить-Калисту.command`. Адреса и два ключа находятся в локальном файле `Доступ-к-игре.txt`.
Другу передай адрес для телефона и ключ игрока. Оба устройства должны находиться в одной локальной сети.
Ведущий получает уведомление о предложении, нажимает «Обновить игру» и принимает либо отклоняет его в разделе «Бой».

## Запуск из репозитория

Нужен Python 3.12 на macOS или Linux. Из каталога приложения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python kalista_setup.py
.venv/bin/python -m streamlit run kalista_app.py --server.address 0.0.0.0 --server.port 8501
```

Созданные ключи и сохранения остаются локальными и исключены из Git. При размещении на сервере нужно настроить HTTPS и постоянное хранилище; локальный Wi-Fi доступ уже готов.

## Какие правила требуют настройки

Исходный JSON использует кубиковые формулы, а текущий Excel — другие боевые числа. Для когтей, кислотных брызг и облака не задан их перевод в текущий урон и шесть стихий. У «Десницы Ока» одновременно записаны «раз в три хода» и «КД 7 дней»; не определён порядок её пробития. Такие действия видны, но заблокированы до подтверждения настроек ведущим.

Открой «Отряд → Правка → Настроить действия и лимит хода». Задай числа, эффекты и срок, затем отметь, что правила подтверждены. Для «Десницы» можно задать дополнительный 1d6 и вычитание брони, если именно так ведущий трактует исходную запись. Дни отдыха пока учитываются ручной перезарядкой, поскольку игровой календарь не задан.

«Видящий» создаёт описательный статус. Контратака применяется вручную при подходящей ближней атаке; программа не угадывает тип атакующего события. Лечение Шеогарата — выключенная заготовка до задания собственной способности.

## Проверка

Проверены полный раунд, двойная атака и щиты, лечение и заряды, перезарядка, предел стаков, дополнительный бросок, пробитие, лимиты и реакции, сохранение, отмена, два одновременных читателя, предложение игрока, принятие ведущим и защита от повторного применения. Регрессионные проверки правил Калисты и сцен/NPC пройдены.

Автоматический сценарий не заменяет пробную сессию с людьми: её цель — оценить скорость выбора и удобство экранов.

## Файлы программы

- `kalista_app.py` — экраны ведущего и игрока, авторизация и управление сессией.
- `kalista_engine.py` — правила боя, действия, миграции и публичное представление данных.
- `kalista_storage.py` — сохранение с блокировкой, проверкой версии и резервной копией.
- `kalista_theme.py`, `.streamlit/config.toml` — оформление.
- `kalista_setup.py` — создание локальных ключей при первом запуске.
